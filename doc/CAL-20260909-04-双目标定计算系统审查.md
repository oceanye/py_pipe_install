## 已确认的旧故障

`2026-09-09 11:33:01` 的旧算法记录为：左/右单目 RMS `0.715/0.748 px`，双目 RMS `30.252 px`，基线 `2773.94 mm`，矫正焦距 `15159.5 px`，主点横坐标 `-14232 px`。这些数值彼此一致地说明左右单目可以分别拟合，但左右对应或右目画面方向不满足同一刚体模型。

旧算法在固定内参双目求解失败后会改用“联合修改两目内参”的回退。该回退能把错误的左右对应吸收到焦距、主点和基线中，产生看似完整但物理上失真的结果。该路径已经删除。

## 当前计算链

1. 棋盘物点按 `square_mm` 生成毫米坐标；界面中的横向/纵向数是方格数，求解时使用各减一后的内角点数。
2. 每组左右角点先按完整网格的横、纵方向统一 180° 标签顺序，不再用首角点距离判断。
3. 左右相机分别求 K/D；双目阶段固定 K/D，只求刚体 `R/T`。
4. 原始方向发生系统性大误差时，比较右目的水平翻转、垂直翻转和 180° 旋转。候选不仅比较 RMS，还必须满足水平基线和正视差几何，避免选中数值较低但方向错误的解。
5. 逐组误差用中位数和 MAD 检测异常；一次最多剔除总数的 20%，并保留至少 `min_pairs` 组。被剔除的原始组号写入审计。
6. 用 `stereoRectify(alpha=0, CALIB_ZERO_DISPARITY)` 生成 R1/R2/P1/P2。现场深度只使用经过该配方转换后的图像。
7. 深度计算所需关系被显式核对：`B = ||T||`、`B = -P2[0,3]/P2[0,0]`、`d = x_left - x_right > 0`、`Z = fx·B/d`。

## 保存前必须同时通过的门禁

| 类别 | 门禁 |
|---|---|
| 数量与覆盖 | 至少配置的照片组数；至少 6 个画面区域；质心散布比不小于 `0.10` |
| 姿态激励 | 棋盘倾斜跨度不小于 `8°`；距离散布比不小于 `0.08`；每组均能恢复有限的正深度姿态 |
| 重投影 | 左目、右目、固定内参双目 RMS 均不超过界面配置值 |
| 原始内参 | 焦距在图像最大边长的 `0.2–4.0` 倍内；主点位于图像内；畸变系数有限且绝对值不超过 `5` |
| 基线 | 求解基线在 `20–2000 mm`；填写实测镜头中心距后，误差不得超过 `max(3 mm, 15%)` |
| 极线 | 左右 P 矩阵共享相同 K；垂直残差 RMS 不超过配置 RMS，P95 不超过 `max(1 px, 2×配置 RMS)` |
| 方向 | P2 编码正的水平基线且与 `||T||` 一致；垂直投影基线近零；中位视差为正且至少 98% 棋盘角点为正视差 |
| 持久化 | 配方 ID、图像尺寸、矫正 K 和基线必须与标定完全匹配；任一不一致均拒绝载入 |

## 数据一致性修复

- 右目画面修正属于“原始帧到矫正帧”的配方，现保存到 `rectification_recipe.right_frame_transform`，由 `Rectifier` 在右目重映射前应用。它不再保存到相机设备选择中。
- 可兼容读取短期旧版本放在 `camera.right_frame_transform` 的配置，并自动迁移到配方，避免升级后丢失已选方向。
- 同一轮标定不能混用 SB 与 classic 两种角点检测器。SB 原生异常后左右目一起切换；若已有照片使用了另一检测器，界面会清除旧组并重新计数。离线文件夹标定统一使用 classic。
- 离线标定不再允许 `0` 或 `None` 关闭 RMS 门禁；未指定时使用 `1.5 px`。未通过门禁时不再输出“成功”标定。
- 离线输出现在包含标定和完整极线配方的便携 JSON；导入后不会丢失右目修正或原始 K/D/R/P。
- 求解拒绝或 OpenCV 数值异常时保存全部角点、区域和检测器到 `outputs/measurement_workbench/calibration_diagnostics/*.npz`。可运行：

  ```powershell
  .\.venv\Scripts\python.exe .\scripts\replay_calibration_diagnostic.py <诊断文件.npz>
  ```
