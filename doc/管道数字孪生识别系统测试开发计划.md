# 管道数字孪生识别系统测试开发计划

> 文档版本：v0.3（M0 单层演示 + M1 两层合成双目/遮挡基线）
> 编制日期：2026-08-31
> 适用阶段：技术验证、工程开发、现场影子运行与生产验收
> 输入依据：[需求文档](./需求文档.txt)、[轮廓与三维模型迁移指南](./camera_contour_3d_pipe_migration_guide.md)、[M0 manifest](../test_model/manifest.json)、[M1 manifest](../test_model/pipe_group2_manifest.json)、[管道群2说明](./管道群2模拟双目与遮挡拓扑说明.md)

## 1. 计划目的

本计划用于把当前概念方案推进为一套可测试、可回放、可审计、可逐步验收的管道安装状态识别系统。当前交付包括 **M0 单层离线演示基线**和 **M1 两层 CAD 合成双目/遮挡拓扑基线**。M0 验证颜色识别、投影直径二次校验、显隐事件提取和报告契约；M1 从 9 管两层 3MF 生成左右 RGB、精确 CAD 深度、实例所有权、正交立面与有向遮挡关系。后续阶段再覆盖：

- 数字孪生和 CAD 几何底座；
- 固定双目/多机位真实图像采集；
- OpenCV 轮廓、双目深度和 CAD 投影比对；
- 管道级证据融合与安装状态机；
- 实例分割、多模态模型等辅助算法；
- 5～60 分钟周期性巡检；
- 边缘部署、断网续传、审计和离线重放；
- 后期多机位及 3DGS 派生场景预留。

项目采用“证据优先、安全拒判”的原则。M0 必须遵守 `not_observed != not_installed`：录屏中未观测到对象不能自动解释为未安装。后续真实视觉阶段在完全遮挡、标定失效、同步失败、深度不可用或模型版本不一致时，系统必须输出 `UNKNOWN/UNDETERMINED/ERROR`，不得用安装计划、历史状态、VLM 或 3DGS 生成虚假的视觉确认。

### 2.1 当前资产事实与限制

1. 3MF 明确使用毫米，包含 D20 白管、D40 红管、D45 蓝管三根长 500 mm 的独立封闭三角网格，当前 manifest 将它们全部归入 `layer_id=L0`。
2. 3MF 只提供网格、颜色和技术对象 ID/UUID，没有壁厚、端口、连接拓扑、安装状态或稳定业务 ID；身份必须由 manifest 的 `pipe_id` 显式绑定。
3. MKV 是 1920×1080、60 fps 的固定视口 CAD 桌面录屏，没有内参、外参、畸变、物理尺度、深度、对象 ID mask 或同步相机语义。
4. M0 只验证“颜色主识别 + 投影直径二次校验”。投影直径是像素域的非标定量测；3MF 的 D20/D40/D45 只能作为模型先验/类别桶，不能据此声称从 MKV 测得了物理管径，也不能替代 D22/D50 实物验收。
5. `not_observed` 仅表示当前帧未形成有效观测，可能来自 CAD 显隐、遮挡、出画、画质或算法失败，绝不等于 `not_installed`。
6. 当前仍没有真实相机型号、`camera.json`、内外参、双目基线、安装顺序或现场图片；迁移指南引用的 Android/C++ 源码、配置和测试资产也不在本仓库。
7. `管道群2.3mf` 为毫米单位，含 9 根沿 X 轴、长 500 mm 的封闭网格：前层 3 根、后层 6 根；颜色和直径是独立属性，稳定身份来自 manifest。
8. M1 虚拟相机参数和 CAD 深度是确定性算法真值，不是现场标定结果；`管道群2.mkv` 全程相机固定且仅切换对象显隐，不能作为双目、深度或 3DGS 多视图输入。

在真实传感器、标定、尺度真值和业务状态证据补齐前，禁止宣称 M0 已完成现场尺寸量测或生产安装状态验收。

## 3. 项目成功标准

### 3.0 M0 退出标准

- `manifest.json` 能确定性加载单层 `L0` 的 D20/D40/D45 三根管，并校验 3MF/MKV 哈希与基础元数据；
- 颜色规则生成身份候选，投影直径桶仅作二次校验；当前匹配输出 `MATCHED`，无候选或冲突安全降级为 `UNKNOWN`，不得强制分配；独立 `AMBIGUOUS` 枚举列为下一阶段契约；
- 报告保留原始 `diameter_px`；派生的 `projected_diameter_estimate_mm` 必须标记 `diameter_source=model_prior`、`metric_calibrated=false`，不得伪装为现场毫米量测；
- 可见性逐帧准确率、事件边界误差和稳定段假转移满足 manifest 中的 M0 验收阈值；
- `NOT_OBSERVED` 不触发 `not_installed/MISSING`；输入资产、manifest 哈希和软件版本可追溯，状态、区间及评价指标可重放；
- 仓库根目录可按第 7 节约定命令生成 `outputs/current_demo_report.json`。

### 3.0.1 M1 合成双目/遮挡退出标准

- manifest 绑定 9 个 CAD object/UUID、稳定实例 ID、独立颜色/直径、前后层和三维中心线，并校验 3MF SHA-256；
- 左右虚拟相机明确输出 K、`T_camera_world`、95 mm 基线、无畸变和 `camera_z_mm` 深度语义；
- 左右真值以 `float32 depth_z_mm`（背景 `NaN`）和 `uint16 instance_id`（背景 0）保存，RGB 颜色不作为实例身份；
- 正交立面输出逐管完整/可见轮廓、可见比例、遮挡状态、遮挡矩阵和有向图；后层实例 7、9 的完全遮挡回归必须稳定；
- 对每个视点，`FULLY_OCCLUDED` 只表示设计对象无自有像素，绝不得推导为 `NOT_INSTALLED/MISSING`；
- 同一 manifest 重生成的结构化真值、数组内容及文件清单可重复，测试在 Windows/Linux Python 3.12 通过。

生产目标最终还需要同时满足以下五类要求。

### 3.1 业务正确性

- 正确识别当前累计安装状态；
- 正确识别正常推进、稳定、错序、拆除/回退和无法判断；
- 不因背景边缘、高光、人员、工具或旧帧错误提前推进；
- 不把遮挡、出画或深度空洞判断为管道缺失；
- 输出管段级证据、置信度、可见性和原因码。

### 3.2 几何与测量可信度

- CAD、相机和现场坐标变换可追溯；
- 后续最小 D22 实管在最远设计工作面具备足够像素宽度；M0 录屏不参与该物理门禁；
- 左右轮廓、深度、实例 mask 分别保留质量指标；
- 圆柱沿轴平移和绕轴旋转等不可观自由度必须明确标记；
- 任何位姿或尺寸结论都有误差预算或不确定度。

### 3.3 安全降级

- 相机、标定、同步、CAD、配置或算法健康检查失败时不提交新状态；
- `UNKNOWN` 与 `MISSING` 严格分开；
- `INFERRED/PRIOR_ONLY` 与 `VERIFIED` 严格分开；
- 状态提交幂等，重复任务、重启和重复上传不得造成二次推进。

### 3.4 工程可靠性

- 5 分钟最高频率下可长期稳定运行；
- 断网时先在边缘持久化，恢复后幂等补传；
- 任意一次判断可从原始证据和版本信息完整重放；
- 代码、CAD、标定、配置和模型均有版本与哈希。

### 3.5 可扩展性

- 增加或移除机位不修改核心状态机；
- 多机位按世界坐标中的独立证据进行 late fusion；
- 可导出 COLMAP/3DGS 所需的相机、位姿和帧组数据；
- 3DGS、VLM、学习式深度均通过插件接口隔离。

## 4. 被测系统总体结构

```text
当前 M0：3MF + MKV + manifest
             ↓ 资产/hash/单层 L0 校验
           OpenCV 颜色候选
             ↓ 投影宽度/直径桶二次校验（像素域、非标定）
           FrameObservation
             ↓ 稳定帧聚合与显隐事件提取
           DemoReport
             └─ VISIBLE / NOT_OBSERVED + MATCHED / UNKNOWN
                不产生 not_installed 或生产 StateTransition

后续离线：STEP/SAT/IFC → 几何转换与语义校验
                        → TwinManifest + PipeSegment + 安装状态 DAG
                        → CAD depth / instance_id / contour / visibility 渲染

后续在线：Scheduler → 同步 CaptureGroup + 标定健康检查
                    → RGB 双侧轮廓 / disparity-depth / mask
                    → 每相机 PipeEvidence
                    → 多机位 late fusion + 安装顺序状态机
                    → StateTransition + append-only 审计事件

后期派生：冻结 SceneEpochPackage → COLMAP 导出 → 3DGS worker
          仅输出可视化资产，不得提交 StateTransition
```

## 5. 状态与证据模型

状态必须拆成正交维度，避免一个“置信度”掩盖不同失败原因。尤其不得把 M0 的画面可见性直接复用为生产安装状态。

### 5.0 当前 M0 画面观测状态

- `visibility=VISIBLE`：当前帧形成满足颜色、形状和投影直径二次校验的视觉观测；
- `visibility=NOT_OBSERVED`：当前帧没有形成该对象的有效观测；
- `decision=MATCHED`：候选通过颜色和投影直径门禁；
- `decision=UNKNOWN`：无有效候选或无法安全匹配；
- `installation_state=UNKNOWN`：当前 M0 对所有管始终成立，不从画面显隐推导安装状态。

独立的 `AMBIGUOUS`、`INVALID_FRAME` 及相应 reason code 是下一阶段需要冻结的显式枚举；当前解码/输入格式失败由 CLI 非零退出，不会伪造业务状态。

硬约束为 `not_observed != not_installed`。M0 没有真实现场、标定、遮挡自由空间或业务证据，因此不允许输出生产含义的 `MISSING`。

### 5.1 元件观测状态

- `PRESENT`：当前观测支持管段存在；
- `MISSING`：在健康、可见条件下存在可信自由空间证据；
- `UNKNOWN`：不可见、遮挡、无效深度或证据不足；
- `EXTRA`：发现 CAD 中未预期的占据或构件；
- `CONFLICT`：不同机位或模态产生不可安全融合的冲突。

### 5.2 证据等级

- `VERIFIED`：当前健康观测直接支持；
- `INFERRED`：依据历史和安装顺序推断，但当前没有完整直接证据；
- `PRIOR_ONLY`：只来自计划、初始化或不可观自由度先验。

### 5.3 系统健康状态

- `OK`
- `CALIBRATION_INVALID`
- `SYNC_INVALID`
- `DEPTH_DEGRADED`
- `OCCLUDED`
- `OUT_OF_FOV`
- `CAPTURE_FAILED`
- `MODEL_REVISION_MISMATCH`
- `STORAGE_DEGRADED`

### 5.4 全局施工状态

- `S0…Sn`：合法累计安装状态；
- `STABLE`：与上次确认状态一致；
- `ADVANCED`：合法向前推进；
- `REGRESSED`：发现疑似拆除或回退；
- `OUT_OF_ORDER`：与安装 DAG 冲突；
- `ANOMALOUS`：存在额外构件、位置异常或非法回退；
- `UNDETERMINED`：无法安全选择状态。

### 5.5 状态机硬约束

1. M0 的 `not_observed` 不得映射为 `not_installed/MISSING`，M0 报告也没有生产 `StateTransition` 写权限。
2. 安装计划只能作为 prior，不能单独生成 `VERIFIED`。
3. 完全遮挡、出画、无效深度或健康失败不得生成确定 `MISSING`。
4. 一侧强轮廓不能代替完整的双侧几何支持。
5. 单机冲突不得直接用简单多数投票掩盖，先进入 `CONFLICT`。
6. 同一 `capture_group_id` 重放多次只允许产生一次业务转移。
7. 拆除先进入异常流程，除非业务明确启用合法拆除状态边。
8. VLM 和 3DGS worker 没有状态写权限。
9. 单轮稳定性主要在短帧组内做 N-of-M 聚合；不能默认要求连续两次巡检才确认，否则 60 分钟模式可能产生约两小时确认延迟。

## 6. 数据契约开发计划

M0 先冻结以下最小对象。所有对象必须有 schema 版本，关键资产必须有 SHA-256。

| M0 对象 | 必填字段摘要 | 必测性质 |
|---|---|---|
| `DatasetManifest` | dataset/model revision、单层 `L0`、3MF/MKV URI 与 hash、ROI、颜色/直径规则、验收阈值 | D20/D40/D45 映射唯一、缺字段拒绝、hash 校验 |
| `PipeSpec` | 稳定 pipe_id、CAD object/UUID、layer_id、颜色、标称直径、完整 3D 中心线 | pipe_id 唯一；颜色/直径冲突可报告，不能隐式改 ID |
| `FrameObservation` | frame、时间戳、每管观测状态、颜色分数、投影宽度 px、模型归一化直径候选和原因码 | 仅在使用 `--observations` 时写入 JSONL；原始量测保留 px；派生 mm 字段必须声明 model_prior/非标定；候选可多值 |
| `DemoReport` | 输入资产/manifest hash、model revision、软件版本、模型/视频审计、量测摘要、稳定区间、显隐事件、验收汇总、limitations | 忽略动态 `generated_at` 后，检测状态、区间和评价指标可重放；`NOT_OBSERVED` 不生成安装状态 |

为未来多层、双目、多机位和 3DGS 保留以下版本化对象：

| 对象 | 必填字段摘要 | 必测性质 |
|---|---|---|
| `TwinManifest` | 项目、单位、坐标约定、CAD/配置版本 | 缺字段拒绝、兼容性、hash 校验 |
| `GeometryAsset` | 来源、转换器、B-Rep/mesh、包围盒、体积、LOD | 重复导入确定性、单位一致性 |
| `PipeSegment` | design_id、轴线、直径、长度、连接、前驱、容差 | ID 唯一、拓扑和语义完整 |
| `CameraCalibration` | camera_id、分辨率、K、畸变、误差、有效期 | 投影/反投影、缩放、过期拒绝 |
| `RigCalibration` | rig_id、`T_rig_camera`、基线、协方差 | 变换闭环、左右顺序、基线符号 |
| `CaptureGroup` | run/group ID、设备时间、曝光中点、同步健康 | 丢帧、乱序、重复和超时 |
| `FrameEnvelope` | 原图 URI/hash、序号、曝光、增益、标定 ID | 不可变、幂等写入、来源完整 |
| `ObservationProduct` | disparity/depth/mask/confidence、单位、算法版本 | invalid/scale、输入引用完整 |
| `PipeEvidence` | pipe_id、view、状态、分数、可见性、原因码 | 遮挡与缺失逻辑 |
| `StateTransition` | 前后状态、证据引用、策略版本、提交者 | 合法边、幂等和可重放 |
| `SceneEpochPackage` | 冻结帧集、相机位姿、动态 mask、全部 hash | COLMAP round-trip |
| `GaussianSceneAsset` | epoch、训练版本、参数、模型 URI/hash | 只读回挂、权限隔离 |

坐标变换统一命名为 `T_target_source`，表示把 source 坐标点映射到 target。M0 的 3MF 模型长度单位为毫米，原始图像量测单位为像素；无标定时不得把两者转换成现场物理尺寸。若为分类二次校验生成模型归一化的 `projected_diameter_estimate_mm`，必须同时携带 `diameter_source=model_prior` 和 `metric_calibrated=false`。后续 P0/P1 必须冻结右手系、相机轴、像素中心、矩阵存储顺序和唯一权威长度单位。建议权威孪生存储使用 SI 米；若轮廓算法内部使用毫米，只能在有类型和测试覆盖的边界显式转换，禁止无单位浮点数跨模块传递。

## 7. M0/M1 运行约定与建议代码结构

M0 运行时依赖固定为 `numpy` 和 `opencv-python-headless`，从仓库根目录执行：

```powershell
python -m pipe_twin analyze --manifest test_model/manifest.json --output outputs/current_demo_report.json
```

该入口读取 manifest 中的 3MF/MKV、颜色规则、投影直径二次校验和验收阈值。默认报告还包括模型/视频审计、非标定量测摘要和验收结果；追加 `--observations outputs/current_demo_observations.jsonl` 才会保存逐帧证据。输出必须明确 `metric_calibrated=false`。

M1 使用同一组锁定依赖，从 CAD 重建合成双目和立面黄金样例：

```powershell
python -m pipe_twin simulate-stereo --manifest test_model/pipe_group2_manifest.json --output-dir test_model/pipe_group2_synthetic_stereo
```

## 9. 相机选型与 1 m 台架测试

本节属于 M0 之后的真实传感器阶段。当前 MKV 录屏不得用于相机选型、尺度精度或双目性能验收。

### 9.1 候选路线

建议并测：

1. 长基线被动双目；
2. 工业主动双目/RGB-D；
3. 工业 ToF 或投影纹理双目作为低纹理补充候选。

各候选必须能提供原始左右帧、实际运行模式的 K/畸变/基线、时间戳、曝光/增益和深度 invalid/confidence，不接受只提供厂商 Viewer 截图的设备。

### 9.2 纸面与计算门禁

使用校正后实际参数，而不是营销分辨率：

```text
p22 = fx × 22 / Zfar
scene_width = W × Z / fx
disparity = fx × B / Z
sigma_Z = Z² × sigma_d / (fx × B)
```

初始规划目标：

- 名义 1 m 工作面，D22 投影宽度推荐至少 24 px；PoC 硬下限 20 px；
- 0.8～1.2 m 压力范围的最远位置仍不得低于 20 px；
- 推荐双目基线 `B ≥ 95 mm`；
- 若需要以 3σ 区分 20 mm 前后层差，在实测 `sigma_d ≤ 0.5 px` 前提下，目标 `fx × B ≥ 106000 px·mm`；
- 视场需覆盖生产管群包络，并保留 15%～20% 安装和标定余量；
- 视差搜索范围需覆盖最近工作面，并保留至少 20% 余量。

以上均为 PoC 初值，不是脱离真实表面的采购保证。

### 9.3 实验工装

准备：

- 真实 D22、D50 管，并保留当前 D20/D40/D45 3MF/MKV 作为非标定算法回归资产；
- D22-D22、D50-D50 同规格并排工况；
- 哑光漆、镀锌、亮不锈钢、积尘、沾水/油等表面；
- 可调距离 0.8/1.0/1.2 m；
- 深度台阶 0/10/20/30/50/100 mm；
- 管轴相对像平面 0°/30°/60°；
- 可重复遮挡板、人员/工具/支架干扰物；
- ChArUco/AprilTag 控制点、量块、卡尺和机械定位轨道。

不得使用被测相机自身的深度作为真值。真值必须记录来源、不确定度和校准状态。

### 9.4 两轮 bake-off

**Round 1：快速筛选**

- 每候选约 60～100 个代表条件；
- 每条件至少 50 帧；
- 淘汰像素不足、亮管深度大面积失效、无法锁参数、同步或 SDK 不稳定的设备。

**Round 2：决赛与现场影子测试**

- 两个入围方案跑完整材质、距离、角度、光照和遮挡矩阵；
- 每条件至少 100 帧；
- 在实际安装点 shadow 运行不少于 14 天；
- 最终按业务状态混淆矩阵排名，点云密度和视觉效果只作诊断指标。

## 10. 标定与同步测试

### 10.1 标定流程

1. 固定分辨率、ROI、焦点、曝光策略和去畸变路径后再标定；任何改变都生成新 revision。
2. 内参标定覆盖整个 FOV、不同倾角和 0.8～1.2 m 深度，建议 30～50 组图像。
3. 标定集和独立验证集分开。
4. 双目标定检查基线尺度、共同视场和校正后极线残差。
5. 多机位外参使用共享控制点/标靶并检查变换闭环。
6. CAD→现场外参依靠固定结构上的控制点，不把可拆卸管道作为长期锚点。
7. 冷启动、热稳定和现场温度边界分别复测。

### 10.2 暂定标定门禁

- held-out 重投影 RMS ≤ 0.3 px；
- 校正后垂直极线残差 P95 ≤ 0.5 px，最大值 ≤ 1 px；
- 已知尺度误差 ≤ 0.5%；
- CAD 控制点 overlay P95 ≤ 2 px；
- 在线控制点 P95 ≤ 1 px 为 `GOOD`，1～2 px 为 `WEAK`，大于 2 px 阻止状态提交并要求复标。

这些数值在 P1 结束时由真实设备复核并冻结。

### 10.3 同步测试

- 用 LED/运动时间靶测量曝光时差，而不是只比较文件时间；
- 测硬触发/PTP 锁定、丢锁、重锁和相机重启；
- 测主动设备同时点亮与错时点亮的串扰；
- 测满带宽下的丢帧、乱序和重复帧；
- 允许时间误差由运动像素预算反推：`v_image,max × delta_t ≤ e_sync_px`；
- 超出同步预算的帧组标记 `SYNC_INVALID`，不得参与双目或多机位融合。

## 11. 场景与数据集计划

### 11.1 采集单位

M0 数据集的原子单位是 `3MF + 完整 MKV + manifest`，逐帧结果不得脱离视频、ROI、阈值和模型 revision 单独解释。进入真实采集后，数据集的原子单位是一次 `inspection burst/session`，不是散帧。同一短帧组中的所有帧必须进入同一个数据划分，禁止把相邻帧随机分到训练集和测试集。

每个 burst 保存：

- 左右原始帧和设备/主机时间戳；
- camera/rig ID、分辨率、K、畸变、双目外参和世界外参 revision；
- 曝光、增益、白平衡、温度和同步健康；
- CAD、安装计划、配置、软件和模型 revision/hash；
- 计划状态、人工确认的实际状态、可评估性；
- 管段可见 mask、遮挡者、标注者和 QA 状态；
- disparity/depth/confidence、轮廓、CAD overlay 和最终证据。

### 11.2 场景矩阵

| 维度 | 覆盖值 |
|---|---|
| 管径 | D20/D40/D45 M0 资产回归；D22/D50 实物；D22-D22、D50-D50 同径组合 |
| 距离 | 0.8、1.0、1.2 m |
| 视角 | 侧视、30°/60°斜视、趋近消失点、端面入/不入画 |
| 间距 | 分离、接触、部分重叠、前后层差 0/10/20/30/50/100 mm |
| 遮挡 | 0/10/30/50/70/100%，左侧/右侧/端部/中央分别遮挡 |
| 材质 | 哑光、镀锌、镜面、锈蚀、保温、湿/油/尘 |
| 光照 | 日/夜、低照、局部强光、窗边日光、LED 闪烁、过曝/欠曝 |
| 背景 | 墙缝、线缆、栏杆、支架和比管道更长的平行假边 |
| 业务状态 | 空场、每个合法累计态、错序、拆除、装回、额外构件 |
| 设备异常 | 不同步、旧帧、掉帧、污镜、支架移动、错误 K/CAD、深度空洞 |

不执行上述所有因子的完整笛卡尔积。先用基础条件＋pairwise 设计筛选，再对 D22@1m、镜面、高遮挡、同径重叠、相机漂移等安全关键组合做完整压力覆盖。

### 11.3 数据划分

- 开发数据建议按 session/group 做 60% train、20% validation、20% internal test；
- 另设完全隔离的 sealed acceptance set；
- 分组键至少包含 `site/background + physical_camera + date/session + installation_sequence`；
- acceptance set 至少包含新日期、新灯光/背景和不同安装人员；
- 多机位阶段加入 leave-one-camera/view-out；
- 合成数据主要进入训练集，只用于数学正确性和启动训练，不能代替现场验收；
- 密封集一旦用于调参即失去密封资格，必须重新建立。

### 11.4 标注与真值

- 可见 mask 只标当前实际可见部分，不臆测遮挡后的完整轮廓；
- 完全遮挡不标 `PRESENT/MISSING`，而标 `UNKNOWN/not_assessable`；
- acceptance 标注至少双人复核，分歧由领域负责人裁决；
- 台架使用已测量工装、卡尺/量块和控制点；
- 现场存在性使用施工日志与同步影像交叉确认；
- 每个真值字段记录来源和不确定度。

## 12. 测试金字塔

本节的 `L0～L5` 表示测试层级，与 M0 manifest 中的场景 `layer_id=L0` 无关。

### L0 单元测试

- schema、单位和坐标变换；
- K 随分辨率缩放；
- 畸变和预去畸变路径互斥；
- 圆柱解析投影、轮廓左右排序；
- 图像边界伪闭合排除；
- Jacobian 有限差分；
- 轴向平移/roll 不可观断言；
- 状态机所有合法/非法边；
- run/event ID 和幂等键生成。

### L1 合成与性质测试

- 已知精确真值下扫描直径、距离、视角和遮挡；
- 解析圆柱与高分段 mesh 投影一致；
- 随机生成重复、乱序、丢失和矛盾事件；
- 固定种子的黄金图像和结果回归；
- CAD/标定扰动敏感性和可观测性矩阵。

### L2 离线真实回放

- 同一原始 burst 对不同版本做 paired comparison；
- 输出完整中间证据而非只保存最终状态；
- 支持无 GPU、目标边缘设备和服务器三类环境重放；
- 最终离散状态必须一致，浮点结果在声明容差内。

### L3 受控台架

- 已知位置、距离、层差、光照和遮挡；
- 验证像素、深度、轮廓和业务状态；
- 测相机平移/旋转、镜窗污染和温漂；
- 测 D22/D50 真实材料；D20/D40/D45 仅保留为 M0 合成回归规格。

### L4 现场 shadow

- 不写生产孪生、不直接告警；
- 与人工安装日志对账；
- 运行 2～4 周，覆盖实际班次和环境；
- 形成失败案例库和阈值冻结报告。

### L5 持续回归

- 每次代码、模型、CAD、标定或配置变更均执行对应回归；
- 安全关键桶不允许被总体平均指标掩盖；
- 发布前必须跑密封回放、硬件 smoke 和故障注入子集。

## 14. 指标体系

### 14.1 几何和标定

- 重投影 RMS、极线垂直残差 P50/P95；
- 1 m 已知平面深度 bias、P95、invalid ratio；
- CAD 控制点投影误差；
- 双侧同时检出率、每侧 support、有效长度覆盖率；
- 中心线误差 px/mm、宽度误差 px/%、方向误差；
- 三维轴线横向距离和角度误差；
- Hessian 条件数和不可观自由度报告。

### 14.2 分割与语义

- mask AP、IoU、Boundary-F；
- 按管径、距离、材质和遮挡分桶的 precision/recall；
- 相邻管合并率、长管断裂率、ID switch；
- 遮挡物 recall；
- 量化前后指标变化。

### 14.3 业务状态

- `PRESENT/MISSING/UNKNOWN` 混淆矩阵；
- 错误提前推进率；
- 错误 MISSING 率；
- UNKNOWN 正确拒判率和正常条件 UNKNOWN 率；
- 错序检出率；
- 状态抖动、错误回退和恢复时间；
- 每个相邻安装状态的混淆矩阵。

### 14.4 性能和可靠性

- 单 run 端到端 P50/P95/max；
- 计划触发 jitter、漏跑率、重复率；
- CPU/GPU/内存/温度和持续增长；
- 磁盘日增量、backlog 和恢复时间；
- 相机、同步和标定健康率；
- 人工复核比例和平均复核时间。

### 14.5 VLM 和 3DGS

- VLM schema 有效率、正确拒答率、证据可定位率、自信错误率；
- VLM 状态写入次数必须恒为 0；

- 3DGS 视觉质量不得替代安装状态指标。

## 15. 发布与验收门禁

### 15.1 永久硬门禁

以下任一失败即禁止发布：

1. schema、单位、坐标和状态机安全性质测试未全部通过；
2. M0 把模型归一化直径冒充现场毫米量测、遗漏 `diameter_source=model_prior/metric_calibrated=false`，或把 `not_observed` 映射为 `not_installed/MISSING`；
3. 单位、K、分辨率、标定、相机序列号、CAD 或配置 revision 不匹配仍继续判定；
4. 完全遮挡、不可评估或健康失败时输出确定 PRESENT/MISSING；
5. 一侧支持被错误提升为双侧 GOOD；
6. VLM 或 3DGS 能直接提交状态；
7. 重启、重复任务或重复上传造成重复推进；
8. 密封验收集中出现错误提前推进；
9. D22@1m、同径并排、强高光、单侧遮挡、相机漂移等关键桶出现未解释回退。

### 15.2 M0 验收目标

- 使用约定命令成功生成 `outputs/current_demo_report.json`；
- 3MF/MKV/manifest 的路径、SHA-256、分辨率、帧率、帧数、对象数和 D20/D40/D45 映射校验通过；
- 可见性逐帧准确率 ≥ 0.995；
- 显隐事件边界误差 ≤ 2 帧；
- 稳定区间假转移数为 0；
- 所有原始投影直径保留 px；任何 `projected_diameter_estimate_mm` 均带 `diameter_source=model_prior` 和 `metric_calibrated=false`；
- `not_observed → not_installed/MISSING` 的非法推断次数为 0。

### 15.3 后续现场 PoC 暂定目标

这些目标在 P1/P3 用真实硬件和业务容差复核后冻结：

- D22@1m 有效宽度 P5 ≥ 24 px；压力边界 ≥ 20 px；
- 标定重投影 RMS ≤ 0.3 px，极线残差 P95 ≤ 0.5 px；
- CAD anchor overlay P95 ≤ 2 px；
- assessable 场景双侧同时检出率 ≥ 98%；
- 中心线误差 P95 ≤ 2 px；
- 宽度误差 P95 ≤ `min(2 px, 10% 投影直径)`；若该公式小于实际标注噪声，需重新分配误差预算并记录原因；
- 方向误差 P95 ≤ 1°；
- 三维轴线横向误差 P95 ≤ 3 mm、角误差 P95 ≤ 1°，或不超过业务公差预算的 1/3；
- pipe 实例 precision ≥ 99%、recall ≥ 98%，遮挡物 recall ≥ 95%；
- 错误 MISSING ≤ 0.5%，错误状态推进目标为 0；
- not_assessable 正确输出 UNKNOWN ≥ 99%；
- 单 burst 端到端 P95 ≤ 30 s，hard timeout ≤ 120 s；
- 5 min 模式 14 天共 4032 个计划 slot，在非注入故障下 0 漏跑、0 重复提交；
- 设计最长断网期间 0 未审计数据丢失。

所有比例必须报告样本数和 95% 置信区间。若要用“零错误”证明真实错误率的 95% 上界低于 0.1%，约需要 3000 次相互独立、可评估且零错误的巡检；同一静态 burst 的连续帧不能当作独立样本。

### 15.4 版本非劣门禁

- 在同一密封集做 paired comparison；
- 关键风险指标的置信区间上界不得恶化；
- 普通指标允许的回退不得超过预先定义的测量噪声或 1 个百分点，取更严者；
- 安全关键桶不允许用总体平均提升抵消；
- 每个发布包绑定代码提交、依赖锁、模型 hash、训练数据 manifest、合成配置/seed、阈值、CAD、标定和运行环境。

## 16. Scheduler、容量与断网计划

### 16.1 Scheduler

- 支持 5/15/30/60 min 和人工立即触发；
- 用 UTC slot 与 station/config revision 生成确定性 run ID；
- 质量失败允许有限重试，禁止无限重试形成队列雪崩；
- 漏过的历史 slot 不默认批量补跑，只保留可审计 `SKIPPED/ERROR`；
- 周期改变只影响发现延迟，不得改变同一 burst 的识别结果；
- 设备 heartbeat 可独立于图像巡检运行，不等同于实时视觉跟踪。

### 16.2 容量

先实测单 run 留存量 `S_MB`，按下式配置：

```text
capacity >= runs_per_day × S_MB × offline_days × 1.3 + OS/model reserve
```

5/15/30/60 min 分别对应 288/96/48/24 run/day。例如 20 MB/run、5 min 模式约 5.76 GB/day。留存策略应优先保存状态变化、异常、低置信和争议 raw；稳定高置信 run 可长期只留精选帧和完整 manifest。

### 16.3 断网与磁盘门禁

- raw/精选证据先原子落盘，再提交 manifest；
- partial 对象不能显示为完成；
- 对象和 manifest 使用 SHA-256；
- 网络恢复后按“异常/状态变化 > 常规”优先级补传；
- 只允许淘汰已确认上传的普通 raw，不得删除未上传异常和 manifest；
- 80/90/95% 磁盘水位分级告警；
- 重传幂等，不产生重复业务事件。

## 17. 多层、双目、多机位与 3DGS 预留计划

### 17.1 从首版开始保存的接口

- `camera_id/rig_id`；
- 原始分辨率、相机模型、K、畸变；
- `T_rig_camera` 和 `T_world_rig(timestamp)`；
- calibration revision、误差和有效期；
- `capture_group_id`、设备时间、曝光中点、同步误差；
- 原始图 URI/hash、曝光/增益/白平衡；
- 动态物体 mask、深度/confidence 和算法版本；
- 场景阶段 `scene_epoch_id` 和对应 CAD revision。

M0 即使只有 `L0` 和一个录屏源，也必须保留全局唯一 `pipe_id`、`layer_id`、完整 3D 中心线、候选数组和 `camera_id/capture_group_id` 占位；不得把二维画面行号或颜色编码成不可扩展的身份。

### 17.2 多层原则

- `layer_id` 是显式分区/先验，不是 pipe 身份；`pipe_id` 在所有层全局唯一；
- 每层记录世界坐标变换和高程范围，每根管保留完整 3D 中心线及误差；
- 可见性与遮挡按 `(pipe_id, camera_id, model_revision)` 建模，后层被遮挡只能输出 UNKNOWN，不能输出 MISSING；
- 同色同径跨层对象必须使用 CAD 投影、深度、空间位置或第二视点消歧；颜色和投影直径不再足够；
- 从单层升级多层只新增 layer、visibility 和 occlusion 数据，不修改 M0 的稳定 pipe_id 和事件审计规则。

### 17.3 多机位原则

- 每台相机先独立输出 Evidence；
- 融合依赖可见性和健康度，而不是盲目平均；
- 新增相机只是新增 Evidence producer；
- 单台离线不得拖垮整站；
- 多主动传感器重叠时评估串扰并支持错时曝光；
- 至少一个视点要最大化相邻安装状态在图像平面的可分离度。

### 17.4 3DGS 边界

3DGS 可用于：

- 场景漫游与远程复核；
- 机位覆盖和遮挡分析；
- 稳定施工阶段的外观档案；
- 后期重定位和数据质检研究。

3DGS 不用于：

- 毫米级尺寸或轴线验收；
- 直接判断管段 GUID、安装顺序或存在/缺失；
- 比较两次 Gaussian 参数来直接生成业务变化；
- 在动态人员未处理、同步失败或视角覆盖不足时强行重建。

一个稳定阶段对应一个冻结的 `SceneEpochPackage`。3DGS worker 只能读取该包并输出 `GaussianSceneAsset`，无状态写权限。原始 Graphdeco 实现存在商业许可限制，工程阶段需单独完成许可证审查或评估许可友好的替代实现。
