# 现场问题记录

## CAM-20260909-01：棋盘格标定窗口打开预览失败

- 日期：2026-09-09
- 状态：已修复，并已在现场 GUI 验证预览打开与自动采集
- 现场现象：点击“检测设备”后再点击“打开预览”，预览没有出现；此前一次预览运行约 20 秒后关闭。

### 日志证据

1. `2026-09-09 10:10:27` 只记录了 `wizard_device_probe_start`，随后程序在 `10:11:00` 关闭。旧实现会扫描索引 0～5 并逐项探测多个分辨率；探测期间点击“打开预览”只更新界面提示，不记录事件，也不会在探测完成后自动启动。
2. `2026-09-09 09:22:34` 相机以索引 0、并排左右模式、每目 `1920×1080` 开始打开，`09:22:36` 成功；`09:22:48` 自动接收一组棋盘格；`09:22:57` 记录 `wizard_preview_failed`，错误为 `Unknown C++ exception from OpenCV code`。

### 原因判断

相机和 `3840×1080` UVC 数据流本身可用。问题包含两个软件原因：

1. 设备与分辨率探测任务会阻止预览启动，但没有排队续接和完整日志，因此表现为按钮无效。
2. 实时预览使用 OpenCV `findChessboardCornersSB` 并启用了适合超大/局部棋盘的 `CALIB_CB_LARGER`。棋盘移动到画面边缘形成局部棋盘时，当前 OpenCV 4.13.0 Windows 构建曾抛出不带详情的原生异常；旧代码把检测器异常当成相机读取失败并关闭整个预览。

### 修复

1. 并排相机检测找到第一个可用设备后立即停止；独立双相机找到两个后停止。
2. 探测期间点击“打开预览”会取消余下探测，并在当前驱动调用结束后自动启动预览，同时记录 `wizard_camera_open_queued` 和续接事件。
3. 实时预览首帧直接显示，后续使用不做额外上采样的 SB 棋盘格检测；正式手动抓拍和离线标定仍使用完整 SB 精度。SB 失败时回退到经典检测器。
4. 移除不适用于固定完整棋盘的 `CALIB_CB_LARGER`。SB 原生异常时自动降级到经典检测器，不再关闭预览。
5. 真正的预览异常会记录失败阶段、异常类型、分辨率、帧序号和完整堆栈；检测器异常按左右目和阶段去重记录。

### 验证

- 自动化测试覆盖：探测提前停止、探测取消、预览排队、SB 异常降级、实时 SB 快速模式、固定棋盘不启用 `CALIB_CB_LARGER`。
- 实机无界面诊断：索引 0 成功输出 `3840×1080`，拆分后左右目均为 `1920×1080×3`；20 秒读取 17 帧，5 轮高精度检测期间相机读帧成功，未出现 OpenCV 异常。
- 现场 GUI 复测：`10:57:01` 记录预览排队，`10:57:02` 自动续接，`10:57:06` 相机打开完成；随后连续自动接收 27 组棋盘格，预览没有再因原生异常关闭。
- 可复测命令：`.\.venv\Scripts\python.exe -u .\scripts\diagnose_stereo_preview.py --index 0 --eye-width 1920 --eye-height 1080 --seconds 20`

### GUI 复测步骤

1. 打开“棋盘格双目标定”。
2. 可直接点击“打开预览”；如果先点了“检测设备”，无需等待探测全部完成，再点“打开预览”会自动续接。
3. 确认左右画面很快出现；移动棋盘到画面边缘后预览应继续运行。
4. 如仍失败，点击“查看完整日志”，按 `wizard_preview_failed.fields.stage` 判断发生在读帧、检测、编码还是界面更新阶段。

## CAL-20260909-02：采集数量足够但双目标定求解未通过

- 日期：2026-09-09
- 状态：代码已修复，等待重启 GUI 后重新采集复测
- 现场现象：自动采集 27 组、覆盖 7 个画面区域后，点击“完成标定并保存”仍被拒绝。

### 日志证据

`2026-09-09 11:02:02` 的 `wizard_solve_rejected` 显示：

- 左右目 RMS：`2.114 / 2.271 px`
- 双目 RMS：`25.314 px`
- 逐视图误差最高：`121.601 px`
- 求得基线：`4974.93 mm`
- 矫正焦距：`11178.9 px`
- 矫正主点：`(-310.2, -8522.6) px`
- 质心散布：`0.12`，覆盖区域 7/9

这组参数在物理上不可信，因此拒绝保存是正确行为，不能通过放宽 RMS 或基线门限解决。

### 原因判断

旧的 `align_pair_orientation` 用左右目“第一个角点的距离”决定是否把右目角点序列旋转 180°。近距离拍摄时，双目水平视差可能大于棋盘在图像中的投影宽度，此时距离规则会选择错误序列。错误序列不妨碍左右相机分别做单目标定，却会破坏左右点的一一对应，典型结果就是单目 RMS 尚可、双目 RMS 极大、基线和主点失真。

本轮实时预览为提升速度曾暂时使用经典检测器，也增加了角点方向在近距离发生歧义的机会。

### 修复

1. 左右角点方向改为比较完整网格的横向、纵向单位方向，不再受固定水平视差大小影响。
2. 接收每组数据时立即完成左右方向对齐，并记录 `right_orientation_flipped`、左右区域和中位视差，便于现场审计。
3. 实时自动采集恢复 SB 检测器；关闭仅影响速度的 `CALIB_CB_ACCURACY` 上采样。完整棋盘识别失败时仍回退到经典检测器，预览不会中断。
4. 质心散布门限由难以在“完整棋盘始终入画”条件下达到的 `0.15` 调整为 `0.10`，同时仍要求至少 6 个区域、RMS、焦距、主点和基线全部通过。界面在采集过程中直接显示当前散布值。

### 复测要求

必须关闭并重新启动 GUI 后重新采集；正在运行的 Python 进程不会自动加载磁盘上的修复。原来的 27 组角点只在旧进程内存中，不应继续用于求解。复测时让完整棋盘覆盖至少 6 个区域，并包含近、中、远距离及前后/左右倾斜角度。
