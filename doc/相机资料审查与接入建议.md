# 相机资料审查与接入建议

本次检查的资料目录为 `doc/双目测距、深度图、标定代码/`。目录包含一段采集示例、双目测距示例、深度图示例、30 对左右照片和一张 `R-C.jpg` 棋盘格照片；用 Unicode 安全读取后，左右照片混有房间画面和手机屏幕上的棋盘，11×7 的 SB 检测器可找到部分左右棋盘对，但整批照片没有通过当前的姿态、尺度、RMS 和极线质量门禁。`R-C.jpg` 是单张打印棋盘示例，能检测到 11×7 内角点，但不是左右配对数据。资料没有可复现的双目标定求解器源码，也没有 CAD 世界坐标中的左目位姿文件。

## 已确认的可复用信息

这里的 640×480 / 11×7 仅指新增资料。现场历史复核确认的是每目 1920×1080、8×6 内角点，见 [现场复核](FIELD-20260911-实测素材与标定复算评估.md)。两批素材的尺寸、板型和基线不得混用；远程部署请按 [交接任务](HANDOFF-REMOTE-CAPTURE.md) 核实现场配置。

- 采集程序把一帧 `1280×480` 的左右拼接图按水平方向拆成两个 `640×480` 目图，左图在前、右图在后。
- 旧配置中的每目内参、畸变、旋转和平移可以被当前的安全适配器读取。平移向量约为 `[-120.3266, 0.1997, -0.2036]`，但原资料没有写明单位，也没有给出 CAD 世界到左相机的位姿，因此系统不会把它直接判为可用于现场三维配准的标定。
- `R-C.jpg` 实际检测到的是 `11×7` 个内角点（即 `12×8` 个方格），而不是当前命令默认的 `9×6`。使用这批图片时应显式传入 `--board-columns 11 --board-rows 7`，并填入实测方格边长。
- 当前标定向导会把左右目角点规范化，并自动修正右图棋盘格可能出现的 180° 顺序翻转；接受记录中会保存 `right_corner_order_rotated_180` 和原始视差审计信息。
- 当前离线标定先严格使用 classic 检测器；只要 classic 已达到最少有效照片对数量就继续使用 classic，只有数量不足时才整批严格改用 SB，且 SB 阶段禁止回退 classic，从而保证不会跨照片对混用两种检测器。中文路径由 Python 先读字节再交给 OpenCV 解码，因此原厂目录可以直接作为输入目录。

## 旧示例不能直接作为现场算法的原因

1. 示例使用 `reprojectImageTo3D(raw, Q)` 后再将三维结果乘以 16。该写法依赖 Q 的常数项与无效点处理，通用流程应明确先用 `raw.astype(float32) / 16` 转为像素视差，再重投影并屏蔽无效点。核实当前 OpenCV 后，`normalize(raw, raw, ..., dtype=CV_8U)` 在源为 int16 时返回新的 uint8 数组，未覆盖原视差；此前把该行认定为已发生原地覆盖的表述不准确。
2. 示例固定设备编号、分辨率和拼接布局，没有检查实际帧尺寸、左右图同步、曝光变化、图像哈希或标定 revision。
3. 示例中有把图像高度写成 `0:640` 的切片，当前素材高度为 480；这不是稳定的输入契约。
4. 旧代码只给出 OpenCV 相机坐标中的 `R/T`，没有把左目绑定到 STL/CAD 世界坐标，不能完成模型到相机的绝对三维配准。

现场流程应继续使用 `StereoCameraSession`、manifest 绑定的标定和当前自动立面分析；旧程序只作为设备采集格式和参数排查的参考。

## 安全接入旧 `camera_config.py`

`pipe_twin.calibration_adapter` 增加了只解析模块级字面量的适配器，不会导入或执行旧 Python 文件：

```python
from pipe_twin.calibration_adapter import adapt_legacy_camera_config

result = adapt_legacy_camera_config(
    r"doc/双目测距、深度图、标定代码/BM_find_distance（测距）/camera_config.py",
    calibration_id="FIELD-LEGACY-01",
    translation_unit="mm",  # 只能填已由设备资料或实测确认的单位
    left_camera_pose={
        "rotation_world_to_camera": [[1, 0, 0], [0, 1, 0], [0, 0, 1]],
        "center_world_mm": [0, 0, 0],
    },
)
```

上面的位姿仅是调用形状示例，不能作为现场真实位姿。该兼容适配器用于原有 CAD 世界坐标工作流；相机几何验证与 CAD 配准验证分别对应 `validated` 和 `registration_validated`。基础自动立面模式可在左矫正相机坐标中重建并自动匹配 STL，不需要先人工测量 CAD 相机位姿。

也可以使用命令行完成同一转换：

```powershell
python -m pipe_twin adapt-legacy-calibration `
  --source "doc/双目测距、深度图、标定代码/BM_find_distance（测距）/camera_config.py" `
  --output calibration/legacy_stereo.json `
  --calibration-id FIELD-LEGACY-01 `
  --translation-unit mm `
  --left-pose-json calibration/left_pose.json
```

命令会把原文件 SHA-256、原始 K/D/R/T、`R1/R2/P1/P2`、采集布局和显式单位写入审计字段；不执行旧脚本，不猜测 `T` 单位或 CAD 外参，并默认输出未验证标定。当前 GUI 仍选择 manifest 标定 JSON；先转换并完成人工复核，再在 GUI 载入 JSON。

## 迁移结论

| 原厂资料 | 当前接入 | 结论 |
| --- | --- | --- |
| `camera_config.py` 的 K/D/R/T、映射和 Q | `calibration_adapter`、`calibration_wizard`、`stereo_analyzer` | 已保留并可转换；单位和 CAD 左目位姿必须显式提供 |
| `capture.py` 的 1280×480 左右拼接采集 | `StereoCameraSession`、`capture-stereo`、远程采集代理 | 已迁移为带尺寸、同步、哈希和日志门禁的采集链 |
| `BM_find_distance/main.py` | 校正、左右一致性、视差和 CAD 投影 | 已迁移为受控实现，修正原脚本固定设备号和高度切片问题 |
| `Depth/main.py` | SGBM、浮点视差、深度有效性和质量门禁 | 已迁移为受控实现；参数与原脚本不逐行相同 |
| 原厂“标定”目录 | 当前 `calibration_wizard` 的 OpenCV 求解器 | 原资料本身没有求解器；必须用新的成对真实棋盘照片重新标定 |

因此，代码路径已经覆盖原厂示例的采集、矫正、深度和配置迁移用途，但原厂照片和 `T` 数值本身还不能产生一份可用于现场验收的真实标定。完整现场闭环仍需同一分辨率下的多姿态左右棋盘对、方格实测尺寸、`T` 单位确认和 CAD 配准验证。

## 建议的现场采集顺序

1. 固定相机分辨率、焦点、曝光和拼接顺序，确认实际每目尺寸与所用标定一致。现场历史为 `1920×1080`，新增资料为 `640×480`。
2. 如需重新标定，按当前板的真实内角点规格和实测方格边长采集多姿态图片。固定旧棋盘可用于采集诊断，不能代替多姿态标定。
3. 在独立棋盘格姿态上检查重投影误差与矫正后的垂直视差；失败时保持 `UNKNOWN`。
4. 基础模式导入 STL，通过双目局部模型自动配准，歧义时辅助指定管长方向或少量基准；完整绝对三维定位模式再使用 CAD 基准点或二维码。
5. 采集现场左右静态图并生成 manifest，确认图像哈希、标定 ID、模型 revision 和分辨率全部一致。

原始压缩包和解压目录均保留在 `doc/` 下，未被修改或删除。
