# CAL-20260909-03：单目标定正常但双目联合求解仍失真

- 日期：2026-09-09
- 状态：已完成方向诊断、固定内参求解和物理/极线门禁加固，等待重启 GUI 后实机复测
- 现场现象：使用上一版角点顺序修复重新采集 26 组后，左右单目标定已明显改善，但双目标定仍被门禁拒绝。

## 日志证据

`2026-09-09 11:33:01` 的 `wizard_solve_rejected` 显示：

- 左右目 RMS：`0.715 / 0.748 px`
- 双目 RMS：`30.252 px`
- 求得基线：`2773.94 mm`
- 矫正焦距：`15159.5 px`
- 矫正主点：`(-14232.0, 744.6) px`
- 覆盖区域：`8/9`，质心散布：`0.133`
- 第 23、24 组单对误差分别高达约 `126/70 px` 和 `117/71 px`

覆盖范围和单目标定已经基本正常，放宽门限不能解决双目几何失真。该组合高度符合其中一路 UVC 画面被驱动镜像或翻转的情况：每只相机单独仍可拟合棋盘格，但左右目之间不存在普通刚体旋转和平移解。

## 修复

1. 双目求解先使用原始方向；出现大于 2 px 的系统性双目误差时，自动比较右目水平翻转、垂直翻转和 180° 旋转后的固定内参解。只有候选方向带来显著改善时才采用，正常设备保持原始方向。
2. 自动选中的右目修正方式写入并绑定到 `rectification_recipe.right_frame_transform`。所有现场抓拍、快速抓拍、标定导出和重新导入均由 `Rectifier` 在极线校正前统一应用，避免标定与测量的数据方向不一致。
3. `wizard_solve_rejected` 新增完整的逐对 RMS 和各方向候选求解结果。失败轮次的全部左右角点会保存到 `outputs/measurement_workbench/calibration_diagnostics/*.npz`，可脱离相机重放分析。
4. 某一路 `findChessboardCornersSB` 首次抛出 OpenCV 原生异常后，本次预览会让左右两路一起切换到经典角点检测；若已有照片使用另一检测器，旧组会被清除，避免混合两套亚像素角点约定。

## 复测要求

关闭当前 GUI，重新启动后再采集一轮。完成求解后检查日志中的 `right_frame_transform_candidates` 和 `right_frame_transform`；若设备确有镜像，预计 `flip_horizontal` 的双目 RMS 会远低于 `none`，程序会自动保存并用于后续抓拍。

## 系统复核补充

后续审查取消了失败后联合修改左右内参的回退路径。现场计算固定两只相机各自独立求得的内参，只求左右相机之间的刚体关系；同时校验原始焦距、主点、畸变、棋盘远近与倾斜跨度、矫正后垂直极线残差、正视差比例及投影矩阵所编码的水平基线。异常照片组最多自动剔除 20%，索引会写入审计；全部原始角点可以通过 `scripts/replay_calibration_diagnostic.py` 离线复算。
