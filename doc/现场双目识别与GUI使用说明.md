# 现场双目识别与 GUI 使用说明

> 版本：v0.1（实物到场前的软件候选版）
> 输入：预网格化 3DM/3MF/STL、已矫正的同步双目静态照片、经验证的相机—CAD 配准
> 输出：每根管唯一的 `INSTALLED / NOT_INSTALLED / UNKNOWN` 及 CAD 状态视图

## 1. 能力边界

STL 使用按连通网格计算的稳定组件 ID 与 `pipe_id` 显式绑定。它不保存标准单位、颜色、图层或业务 ID，因此这些字段必须在导入时由操作员逐管核对。

本版本把 CAD 作为设计对象目录，把左右照片和双目深度作为现场证据。`pipe_id` 与 CAD 对象通过 manifest 中的 `cad_object_id` 显式绑定：3DM 使用 Rhino 对象 GUID，3MF 使用对象 ID。颜色和标称直径是两个独立观测维度，只用于核验候选，不能替代对象身份。

状态语义固定为：

- `INSTALLED（安装）`：至少一个合格视角在该对象的 CAD 投影位置形成颜色、轮廓和双目几何相容的正证据；
- `NOT_INSTALLED（未安装）`：预期位置在画面内、无遮挡，标定/配准/同步/图像质量通过，并且左右目形成自由空间证据；还必须在至少两个独立采集时刻重复缺失；
- `UNKNOWN（不确定）`：完全遮挡、越界、深度无效、画质或标定失败、一次缺失、身份歧义或证据冲突。GUI 使用“不确定”作为唯一中文展示；旧兼容报告可能仍写作“不明”。

因此，第一组照片足以确认部分“安装”，但不用于确认“未安装”。完全被前管覆盖的后管即使存在于 3DM，也必须保持“不确定”（报告枚举 `UNKNOWN`）。

这是一套可运行和可回放的软件候选，不是尚未进行的实物验收结果。现场首轮需要用已知安装/未安装样本调整阈值，任何未通过的门禁都会安全退回 `UNKNOWN`。

## 2. CAD 建模要求

1. 每根受检管道必须是一个独立 Rhino 对象，禁止把多根管合并为一个网格。
2. manifest 必须记录该对象的 GUID；不得按对象名称、显示颜色、管径或列表顺序猜测关联。
3. 模型单位必须明确。加载后统一换算为毫米，并在报告中保留原单位与换算系数。
4. 推荐把每根管转换或另存为 `Mesh`。`rhino3dm` 可以直接读取 Mesh，也可读取 3DM 内已缓存的 BRep/Extrusion 渲染网格，但它不是 Rhino 的几何网格化内核；没有缓存网格的曲面会被拒绝。
5. 当前 M2 要求实例块在导出前展开。缺失网格、重复 GUID、空几何或不支持的实例引用均为硬错误，不允许少读对象后继续判断。
6. 每根管在 manifest 中提供世界坐标中心线、标称外径、设计颜色和层 ID。中心线/外径属于 CAD 先验；相机图像量测独立记录。

如 3DM 不满足第 4～5 条，可在 Rhino 中复制出检查专用版本，将管道对象网格化并展开 Block；也可以导出确定性的 3MF 后沿用同一 `pipe_id` 映射。

### 2.1 STL 导入要求

现场数据录入时必须选择 STL 原坐标单位；程序换算为毫米后按互不连接的三角网格拆分管件，并为每个组件计算与文件顺序无关的稳定 ID。相接、焊接或共享顶点的多个实体会成为一个组件，非直管组件会进入“未纳入对象”清单。自动外径、灰色占位颜色、`P001...` 业务 ID 和组件顺序都需要操作员逐管核对；完成目录后，manifest 会冻结 STL 哈希、原单位和 `pipe_id ↔ cad_object_id` 绑定。

## 3. 双目与配准要求

生产输入是一组离散静态照片，不要求实时视频。巡检周期可设为 5～60 分钟，初值建议 30 分钟；但同一采集组内的左右图必须同步拍摄，不能相隔一个巡检周期。

现场 manifest 必须包含：

- 左右相机 ID、图像尺寸、`fx/fy/cx/cy`、畸变/矫正声明、基线；
- 每个相机的 `rotation_world_to_camera` 和 `center_world_mm`，即 CAD 世界坐标到相机坐标的可追溯配准；
- 标定 ID、验证状态、最大允许同步差；
- 每个 `capture_id` 的左/右照片文件相对路径、SHA-256、带时区时间戳、原始像素方向策略（M2 manifest 路径应指向已矫正、实际送入分析器的照片）；
- 图像/深度/颜色支持率等阈值及其配置版本。

当前 M2 版本要求 `stereo_calibration.rectified=true`，即 manifest 中的左右照片已经是同一输出尺寸、共同极线方向的矫正图。分析器的 SGBM 和深度公式使用水平视差；直接把未矫正原图与普通 K/D/外参字段混用会产生系统性错误，因此会被明确拒绝。若设备只保存原图，应先用 OpenCV `stereoRectify`、`initUndistortRectifyMap` 完成离线矫正，再以矫正图的原始字节和哈希建立 `CaptureGroup`；后续版本再接入自动矫正适配器。

代码只接受 manifest 显式配对，不依据文件名或时间邻近自动猜左右图。输入哈希、尺寸、相机 ID、时间同步或模型哈希不一致时停止本轮，不提交陈旧状态。

### 3.1 相机方向与倾斜校正

GUI 的“相机方向/倾斜校正”用于调整**已经标定并完成极线矫正的整个双目组相对于 CAD 的外参**。可选择相机位于 CAD 的 `+X/-X/+Y/-Y/+Z/-Z` 方向，或沿用当前方向，再输入双目基线中点的 CAD 世界坐标和 yaw/pitch/roll。yaw、pitch 用于相机没有正对预期投影方向时的水平与俯仰校正，roll 用于画面倾斜校正；三者会同时用于 CAD 投影、管道角度匹配、空间定位、中心距/净距和前后顺序。

该操作把左右相机当作刚性双目组，保持标定基线长度及正相机 X 方向，不会再次旋转照片，也不会代替双目极线矫正。每次改变位置或角度都会生成新的可追溯标定 ID；应使用固定控制点复核相机—CAD 配准后再勾选“已验证”。未验证时仍可保存数据，但确定安装状态和尺寸结论会保持待确认。

固定控制点推荐使用尺寸经过实测、刚性安装且角点 CAD 坐标已登记的 ChArUco 或 AprilTag 标定板；普通二维码更适合携带工位/模型编号。单个小型平面码的轴向距离和斜视姿态误差较敏感，毫米级目标应使用较大的标定板或多个空间分散的标记，并记录角点重投影误差和独立量具距离误差。当前 GUI 负责录入和验证外参，尚未自动检测标记板。

### 3.2 直接连接相机

现场数据录入中的“连接双目相机抓拍”会按标定分辨率打开 UVC 设备并显示实时左右预览。单个并排视频流从同一帧拆分左右图，自动记录相同主机时间、设备索引、左右排列和 `SAME_UVC_FRAME` 同步来源；也可选择右左交换或两个独立设备。两个独立设备只能记录并行主机抓帧时间，仍需确认设备具备硬件同步。相机启动初期的黑帧或左右完全相同帧会被拒绝。

### 3.3 D22/D50 与 1 m 工作距离的预检

如果“22/50 mm”指管道外径，不能只凭这两个尺寸或镜头上的焦距标称值判断相机是否满足。应使用矫正输出的实际内参、分辨率和双目基线计算：

```text
D_px = fx_px × D_mm / Z_mm
d_px = fx_px × B_mm / Z_mm
sigma_Z ≈ Z_mm² × sigma_d_px / (fx_px × B_mm)
```

在 `Z=1000 mm` 时，D22 达到 20/24 px 约需 `fx≥909/1091 px`；D50 达到 20/24 px 约需 `fx≥400/480 px`。这只是轮廓可见性预检，还要检查整组管道是否落入视场、遮挡后的剩余像素、曝光/反光和有效视差比例。若要区分约 20 mm 前后层差，需把实测 `sigma_d`、基线和最远工作面代入上式；不能用相机输出的“深度图”自身当真值。明天建议在 0.8/1.0/1.2 m 各拍已安装、未安装、错位重叠和完全遮挡样本，先记录实际 `fx/B/D_px/valid_depth_fraction`，再冻结现场阈值。

## 4. 运行

在仓库根目录创建 Python 3.12 环境并安装：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

检查 3DM/3MF/STL 是否可用于识别：

```powershell
python -m pipe_twin inspect-model path\to\model.3dm --output outputs\model_audit.json
python -m pipe_twin inspect-model path\to\model.stl --stl-unit millimeter --output outputs\stl_model_audit.json
```

未过滤的 3DM 审计会对无网格辅助对象 fail-closed；如果文件中含有未网格化的 Curve/Point/Text/Brep，可重复使用 `--object-id <GUID>` 只审计 manifest 绑定对象。实际 `analyze-stereo` 会自动按 manifest 的 GUID 过滤辅助几何，但不会放宽绑定管道的网格要求。

STL 的 `--stl-unit` 必填，可选 `millimeter/centimeter/meter/inch`。审计会拒绝尾随数据、非有限坐标、零面积三角形和超限模型，并报告每个连通组件的稳定 ID、包围盒和闭合性。

分析一组现场双目静态照片：

```powershell
python -m pipe_twin analyze-stereo --manifest path\to\field_stereo_manifest.json --output outputs\installation_status.json
```

打开 GUI；如果提供报告则只读显示该报告，不提供报告时 GUI 可在后台运行分析：

```powershell
python -m pipe_twin gui --manifest path\to\field_stereo_manifest.json --report outputs\installation_status.json
```

GUI 使用绿色/红色/琥珀色表达三态，同时始终显示中文、英文状态码和原因码，避免只靠颜色传达状态。CAD 状态页是按同一 `pipe_id/GUID` 投影的状态立面/等轴视图；它不是对 3DM 文件的写回，原模型保持只读。

## 5. 实物到场首轮采集清单

建议先布置一套可人工确认的真值组合：至少一根已安装且无遮挡、一根明确未安装、一根部分遮挡、一根完全遮挡。固定相机后依次采集两次同步左右照片，两个时刻之间保持场景不变，以便测试重复负证据门禁。

每次交付以下内容：

1. 原始 `.3dm` 和从 Rhino 读取的对象 GUID 清单；
2. 双目标定文件及其棋盘格/标定板规格、标定日期、重投影误差；
3. CAD—相机配准所用的至少 6 个非共面或有充分空间分布的已知对应点及残差；
4. 两个采集时刻的左右 PNG/JPEG；保留相机原分辨率，不裁剪、不缩放、不做 EXIF 自动旋转。若设备同时保存未矫正原图和矫正输出，manifest 应绑定实际送入分析器的矫正图，并另行留存原图供追溯；
5. 曝光中点时间、相机序列号、焦距/对焦锁定状态、基线实测值和工作距离；
6. 人工真值表：每个 `pipe_id` 的实际安装状态，以及每个相机中可见/部分遮挡/完全遮挡标注。

首轮报告重点查看每根管的左右可见性、颜色支持率、有效视差比例、预测/观测深度残差和原因码。只有这些样本通过后，才能把阈值从“合成回归配置”提升为现场配置。
