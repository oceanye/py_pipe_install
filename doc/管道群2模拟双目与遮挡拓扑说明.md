## 1. 本次交付目标

本次将“管道群2”作为第一套上下投影重叠的两层管道基准，交付两类可重放真值：

1. 一组静态虚拟双目数据：左右 RGB、光轴 Z 深度、稳定实例 ID 和逐相机可见性拓扑；
2. 一份沿世界坐标 `-Z` 观察的正投影立面参考：显式表达管道的上下排列、前后层和“遮挡者 → 被遮挡对象”有向边。

这套数据用于验证 CAD 投影、Z-buffer 归属、双目几何数据契约和遮挡判定逻辑。它不是真实深度相机录像，也不能单独证明管道已安装。

## 3. 虚拟双目相机

### 3.1 坐标与安装方式

- 世界坐标和 3MF 坐标均为右手系，单位为 mm；
- 相机坐标采用 OpenCV 约定：`X` 向右、`Y` 向下、`Z` 向前；
- 左右目均朝向世界 `-Z`，图像水平方向对应世界 `+X`，图像向下对应世界 `-Y`；
- 世界到相机的旋转矩阵为 `diag(1, -1, -1)`；
- 基线沿世界 `X` 方向，与管道轴线平行；
- 深度真值是相机光轴 `Z` 值，不是点到相机中心的欧氏距离。

### 3.2 标定参数

| 参数 | 左目 | 右目 |
|---|---:|---:|
| 分辨率 | 1920×1080 | 1920×1080 |
| `fx`, `fy` | 2637.5783 px | 2637.5783 px |
| `cx`, `cy` | (960, 540) px | (960, 540) px |
| 相机中心 | (202.5, 165.212569, 1020.884848) mm | (297.5, 165.212569, 1020.884848) mm |
| 近/远裁剪面 | 100 / 2000 mm | 100 / 2000 mm |

其他共用参数：

- 基线 `B=95 mm`；
- 水平视场角约 `40°`，垂直视场角约 `23.14°`；
- 前层最近表面的名义工作距离约 `1.0 m`；
- 理想化左右目已矫正，同步误差为 0；
- 不模拟镜头畸变、滚动快门、曝光差、材质反光、噪声、深度空洞或主动投影纹理。

按 `d=fx·B/Z` 估算，管道中心深度对应的视差约在 218～245 px。后续用 OpenCV StereoSGBM 测试时，`numDisparities` 必须覆盖实际距离下的最大视差并取 16 的倍数；不得因默认视差范围过小而把无效区误判为场景缺失。

### 3.3 立面参考相机

立面参考与双目相机使用相同的观察方向，但采用正投影：

- 分辨率 1600×1000；
- 比例 1.5 px/mm；
- 投影中心 `(800, 500)` px；
- 相机中心 `(250, 165.212569, 1020.884848)` mm。

立面图用于表达“上下 + 前后 + 遮挡”几何关系，不使用透视缩小，因此更适合作为设计对照图；它不是任一真实相机的原始帧。

## 4. 生成方法

### 4.1 安装与执行

在仓库根目录中执行：

```powershell
python -m pip install -r requirements.txt
python -m pipe_twin simulate-stereo `
  --manifest test_model/pipe_group2_manifest.json `
  --output-dir test_model/pipe_group2_synthetic_stereo
```

单行命令等价为：

```text
python -m pipe_twin simulate-stereo --manifest test_model/pipe_group2_manifest.json --output-dir test_model/pipe_group2_synthetic_stereo
```

生成器先校验 3MF 的 SHA-256，再从 manifest 绑定 `cad_object_id/UUID` 与稳定 `instance_id`，最后用 CPU 三角形 Z-buffer 生成真值。该过程不依赖 MKV 像素。

### 4.2 当前时间维度

当前命令生成的是一个静态 capture，不是深度视频。把该帧重复 1,800 次只能测试视频封装，不会增加几何信息。若后续需要有意义的模拟深度视频，应在 manifest 中新增逐帧时间戳和左右相机位姿，并为每一帧重新渲染 RGB、深度、实例和拓扑。

## 5. 输出文件与数据语义

| 文件 | 用途 | 是否可作定量真值 |
|---|---|---|
| `camera.json` | 虚拟标定、基线、左右目及立面相机参数 | 是，但只对本次合成数据有效 |
| `left_rgb.png` / `right_rgb.png` | 左右目理想化平滑材质 RGB | 可作投影对照，不适合验证稠密双目匹配 |
| `left_rgb_textured.png` / `right_rgb_textured.png` | 按世界坐标锚定的确定性人工纹理 RGB | 可用于 OpenCV 匹配器试验，但不是真实材质 |
| `left_truth.npz` / `right_truth.npz` | 深度、视差、实例 ID 与双向可对应有效 mask | 是 |
| `*_depth_preview.png` | 归一化深度伪彩预览 | 否，不得从颜色反算 mm |
| `*_instance_preview.png` | 实例 ID 可视化 | 否，真值在 NPZ |
| `left_view_topology.json` / `right_view_topology.json` | 逐相机的可见像素、遮挡比例、遮挡者和状态 | 是 |
| `elevation_reference.png` | 正投影立面 RGB 参考 | 用于人工对照 |
| `elevation_amodal_overlay.png` | 正投影 RGB 上叠加各实例完整 amodal 轮廓和可见性图例 | 用于人工对照 |
| `elevation_reference.svg` | 矢量立面：虚线表示 amodal 轮廓，实显部分表示当前可见区 | 用于人工对照 |
| `elevation_view_topology.json` | 立面视点的管道状态和有向遮挡边 | 是 |
| `occlusion_topology_graph.svg` | 前/后层节点和遮挡边可视化 | 用于人工对照 |
| `occlusion_matrix.csv` | 行=遮挡者，列=被遮挡对象，值=被遮挡对象 amodal 像素占比 | 是 |
| `elevation_continuous_overlap.csv` | 不依赖像素采样的标称截面重叠宽度、目标直径占比和完全覆盖余量 | 是，作为连续几何参考 |
| `dataset_manifest.json` | 数据集版本、来源哈希、实例目录、产物哈希和限制 | 是，作为交付入口 |

NPZ 中的字段契约为：

- `depth_z_mm`：`float32`，单位 mm，背景是 `NaN`；
- `disparity_px`：`float32`，已矫正视差幅值 `fx·baseline/depth`，单位 px，背景是 `NaN`；
- `instance_id`：`uint16`，`0` 表示背景，`1~9` 与 manifest 一一对应；
- `stereo_correspondence_valid`：`bool`，表示该源像素重建点在另一目中仍有同实例、深度一致的可见采样；
- 前景像素应满足 `isfinite(depth_z_mm) == isfinite(disparity_px) == (instance_id > 0)`；
- 几何视差在单目可见但另一目遮挡的像素上仍有数值；评测立体匹配时必须再与 `stereo_correspondence_valid` 取交集；
- 实例身份以 `instance_id/pipe_id` 为准，不得从 RGB 颜色反推真值身份。

读取示例：

```python
import numpy as np

with np.load("test_model/pipe_group2_synthetic_stereo/left_truth.npz") as truth:
    depth_z_mm = truth["depth_z_mm"]
    disparity_px = truth["disparity_px"]
    instance_id = truth["instance_id"]
    stereo_valid = truth["stereo_correspondence_valid"]

assert depth_z_mm.dtype == np.float32
assert disparity_px.dtype == np.float32
assert instance_id.dtype == np.uint16
assert stereo_valid.dtype == np.bool_
assert np.array_equal(np.isfinite(depth_z_mm), instance_id > 0)
assert np.array_equal(np.isfinite(disparity_px), instance_id > 0)
assert not np.any(stereo_valid & (instance_id == 0))
```

## 6. 立面上下关系与遮挡拓扑

### 6.1 两类关系必须分开

1. **上下关系**由世界 `Y` 坐标决定，可以形成从上到下的排序；
2. **前后遮挡关系**由相机深度和轮廓重叠共同决定。只有当两根管在该视点的像素区域重合时，才产生“近管 → 远管”遮挡边。

遮挡边不表示管道物理连接、安装先后或工艺依赖。每个视点都必须单独计算拓扑；立面、左目和右目不得共用未加视点标识的遮挡结论。

### 6.2 正投影立面的预期边

下表是按管径和中心线 Y 区间得到的几何预估，用作生成前的验收 oracle。最终像素占比以 `elevation_view_topology.json` 和 `occlusion_matrix.csv` 为准。

| 遮挡者 → 对象 | 投影重叠宽度预估 | 相对目标直径 | 预期状态 |
|---|---:|---:|---|
| ID 1 红 D40 → ID 4 蓝 D45 | 17.825 mm | 39.61% | ID 4 部分遮挡 |
| ID 1 红 D40 → ID 5 红 D40 | 2.924 mm | 7.31% | ID 5 部分遮挡 |
| ID 2 蓝 D45 → ID 6 蓝 D45 | 5.000 mm | 11.11% | ID 6 部分遮挡 |
| ID 2 蓝 D45 → ID 7 白 D20 | 20.000 mm | 100% | ID 7 完全遮挡 |
| ID 2 蓝 D45 → ID 8 白 D20 | 0.532 mm | 2.66% | ID 8 边缘部分遮挡 |
| ID 3 白 D20 → ID 9 白 D20 | 20.000 mm | 100% | ID 9 完全遮挡 |

因此，立面预期：

- ID 1、2、3 为前层且无其他轮廓覆盖，应为 `FULLY_VISIBLE`；
- ID 4、5、6、8 应为 `PARTIALLY_OCCLUDED`；
- ID 7、9 在这一视点应为 `FULLY_OCCLUDED`；
- 左右目的结果应分别由各自 Z-buffer 重算，不应直接复制立面结论。

### 6.3 状态定义

| 状态 | 当前实现定义 | 是否可视觉评估 |
|---|---|---|
| `FULLY_VISIBLE` | 实例在视锥内，且没有任何 amodal 像素被其他实例占有 | 是，且最大可见连通域需不小于 50 px |
| `PARTIALLY_OCCLUDED` | 仍有可见像素，但至少一个 amodal 像素被其他实例占有 | 是，且最大可见连通域需不小于 50 px |
| `FULLY_OCCLUDED` | amodal 轮廓在视锥内，但可见像素数为 0 | 否 |
| `OUT_OF_FRUSTUM` | 实例的 amodal 轮廓在画面内像素数为 0 | 否 |

`amodal` 表示“如果只渲染该管道，它在画面中应占的完整轮廓”。被遮挡像素的当前 Z-buffer 拥有者用于建立遮挡者列表和有向边。

## 7. 验证要点

生成后至少执行以下检查：

1. `dataset_manifest.json` 中 `domain` 为 `synthetic_cad_truth`，`instance_catalog` 恰有 9 个实例；
2. `camera.json` 中 baseline 为 95 mm，左右目为 rectified，且标记 `field_calibration_validated=false`；
3. 左右 NPZ 尺寸均为 1080×1920，深度/视差/实例前景 mask 完全一致，双向对应有效 mask 只允许是前景的子集；
4. 所有非背景深度位于 100～2000 mm 裁剪范围内，前层深度小于后层；
5. `elevation_view_topology.json` 中 ID 7 和 ID 9 为 `FULLY_OCCLUDED`，且遮挡者分别包含 ID 2 和 ID 3；
6. `occlusion_matrix.csv` 只在“行遮挡者 → 列目标”方向填写非零值，不得当作对称接触矩阵；
7. `elevation_continuous_overlap.csv` 中应恰好记录本文第 6.2 节的 6 条标称截面重叠关系；
8. 各输出文件哈希与 `dataset_manifest.json` 记录相符，同一版代码和输入应可重放。
9. 自动化 OpenCV StereoSGBM smoke 只在 `stereo_correspondence_valid` 区域评价人工纹理版，要求有效覆盖率大于 98%、视差绝对误差 P95 小于 2 px；该门禁证明测试纹理与几何契约可用，不代表真实管材或相机已通过。

## 8. 状态安全边界

- `FULLY_OCCLUDED` 表示“CAD 场景中存在，但在当前视点没有任何自有像素”，不等于 `NOT_INSTALLED`、`MISSING` 或“已拆除”；
- `OUT_OF_FRUSTUM` 和旧 M0 契约中的 `NOT_OBSERVED` 同样不得推进安装状态；
- manifest 中 `all_nine_active` 是本次合成场景的设计先验，不是真实现场的视觉证据；
- ID 7 和 ID 9 在单一立面中完全遮挡时，只能报告“该视点不可视觉核验”。若要核验其实物状态，必须增加其他有效视点或非视觉业务证据；
- 多相机合并时保留每个相机的原始可见性和原因码，只能用“至少一个通过质量门禁的真实视点”提升可见性，不得用 CAD 自动补齐视觉证据；
- 3DGS、VLM 或其他生成模型只可作可视化、ROI 或争议复核辅助，不能将未观测区域生成为“已验证安装”。

## 9. 当前数据能验证什么

### 9.1 可验证

- 3MF 网格到相机像素的确定性投影；
- 左右目内外参、基线和 OpenCV 坐标契约；
- 相机光轴 Z 深度和实例像素归属；
- 前后两层之间的完全/部分遮挡及有向拓扑；
- 颜色与直径在数据结构中作为独立字段传递；
- 视点不可见时的安全拒判契约。

### 9.2 不可验证

- 真实双目的标定误差、时钟同步、曝光差和镜头畸变；
- 白管/高光/反射材质的匹配失效、深度空洞和环境光干扰；
- D22/D50 实管在 0.8/1.0/1.2 m 的实际测径误差；
- 真实现场的安装、缺失、拆除或错序状态；
- 多机位融合或 3DGS 重建质量。

还需要特别注意：当前模型中颜色和管径组合仍然强相关（白=D20、红=D40、蓝=D45）。尽管 manifest 和实例真值已将两者分字段存储，这个场景本身仍不足以证明识别算法真正做到了“颜色与宽度解耦”。后续数据必须同时包含“同色不同径”和“同径不同色”的交叉组合。

## 10. 真实双目后续采集要求

下列内容可直接转发给双目相机测试方。

### 10.1 必须交付的原始资料

1. 相机型号、传感器尺寸、镜头型号/焦距、原生分辨率、像元尺寸、快门类型、基线和深度计算方式；
2. 左右目原始帧，优先无损 PNG 或未经重编码的原始数据，不要只提供拼接预览视频；
3. 每帧的左/右硬件时间戳、帧号、曝光、增益、白平衡、焦距/对焦状态和丢帧标记；
4. 两个相机各自的内参和畸变系数，以及右相机到左相机的 `R/T`、矫正矩阵和 `Q`矩阵；
5. 本次标定所用的原始标定板图片、角点间距、重投影误差和矫正后垂直视差统计；
6. 若设备能输出视差/深度，同时保留原始视差、原始深度、置信度和 invalid mask，不要只保留伪彩图；
7. 现场布置图或尺寸真值：管道 ID、层、标称外径、中心线间距、前后层距离、上下偏移和相机到基准面距离。

### 10.2 采集配置

- 左右目必须使用同一分辨率、裁剪和旋转方式，关闭数字防抖和会改变内参的自动裁剪；
- 相机上架后锁定焦距和对焦；曝光、增益和白平衡尽量锁定并记录；
- 标定图要覆盖图像中心、四角、不同倾角和 0.8/1.0/1.2 m 附近的工作深度，不少于 20 组有效姿态；
- 静态场景也必须记录同步误差。若后续包含人员、工具或管道运动，应使用硬件同步，并以 `<=1 ms` 作为初始建议门槛；
- 标定初始建议门槛为：单目 RMS 重投影误差 `<=0.30 px`，矫正后对应点垂直视差中位数 `<=0.25 px`、P95 `<=0.50 px`。这些数值需在相机型号和现场工况冻结后复核；
- 每个布置至少保留 20 对静态同步原始帧，并额外录制 2～5 s 的同步短帧组以验证稳定性；
- 5～60 min 是后续巡检触发周期，不是左右目允许的时间差。每次巡检内的左右帧仍必须同步。

### 10.3 必须覆盖的场景矩阵

| 维度 | 最低覆盖 |
|---|---|
| 工作距离 | 0.8 m、1.0 m、1.2 m |
| 实管外径 | D22、D50（与当前 CAD D20/D40/D45 分开标记） |
| 可见性 | 无遮挡、边缘部分遮挡、大比例部分遮挡、完全遮挡 |
| 上下错位 | 同中心线、0.25D、0.5D、0.75D 及明显分离 |
| 前后层距 | 至少 3 档已测距离，包含当前约 130 mm 量级 |
| 颜色×直径 | 同色不同径 + 同径不同色；不允许颜色与直径一一绑定 |
| 表面/光照 | 均匀光、侧逆光、高光、白色/低纹理管材，并记录照度 |
| 视野 | 管身中段、管端/接头可见、局部出画 |

对每个“完全遮挡”用例，真值应记录“后管实际存在但该视点不可见”，预期算法输出应是 `FULLY_OCCLUDED/UNKNOWN`，而不是 `MISSING`。

### 10.4 对当前 95 mm 基线方向的特别风险

当前虚拟基线与水平管道轴线平行，同时管身为理想化单色材质。这对几何真值生成没有问题，但对基于 RGB 块匹配的真实双目算法是一个强退化场景：沿极线方向缺少可匹配纹理，可能出现大面积错配或无效深度。

因此真实相机测试必须至少对比：

- 被动双目 + 现有表面纹理；
- 可控制投影纹理/主动双目；
- 保留管端、接头或其他稳定特征的视野；
- 改变相机绕光轴安装角度，使矫正后的极线方向不再与主要管轴方向平行；
- 在 0.8/1.0/1.2 m 下对基线、视差搜索范围、空洞率和边缘飞点率做实测 bake-off。

95 mm 是当前合成基准的测试参数，不是已经验收的现场硬件基线。

## 11. 后续扩展顺序

1. 固化本次静态双目产物和立面拓扑为 M1 回归基准；
2. 加入可配置相机姿态序列，生成有真实时间语义的模拟双目/深度视频；
3. 导入第一批真实双目原始帧和标定文件，对比 OpenCV 视差与合成契约；
4. 增加至少一个明显偏置视点，验证 ID 7/9 能否在其他视点获得可见像素；
5. 在多相机的标定和视点质量门禁通过后，再评估多视图重建和 3DGS；3DGS 仍保持为派生可视化层，不替代原始相机证据。
