# 局部测量工作台

双击仓库根目录的 `run_gui.bat`，或运行：

```powershell
python -m pipe_twin gui
```

主窗口的现场入口只有“基础立面评估”。当前现场流程固定为 **DXF/STL 模型 → 一次双目标定 → 双目抓拍 → 自动匹配 → 状态刷新**。模型中的管道彼此平行时，程序从左右矫正图的共同可见局部建立深度、直径和立面相对位置；颜色只作候选提示和显示，身份主要由双目直径、距离及模型布局决定。

## 第一次建立现场

1. 点击“基础立面评估”，再点击“导入 STL/DXF”。DXF 是侧立面首选：程序读取 `CIRCLE`/`ARC` 外轮廓、对象颜色（没有对象颜色时回退到图层颜色）、管径、默认流水号和共同管长方向。STL 必须选择原坐标单位，程序按连通组件生成管道目录。
2. 点击“相机标定”，选择当前相机、镜头、分辨率和左右布局对应的已验证标定 JSON。状态栏显示标定 ID、分辨率、基线和“相机标定已完成，无需重复”。只有更换相机、镜头、分辨率、裁剪、左右顺序，或发现矫正质量失效时，才打开“重新标定”。棋盘格向导只负责内参、双目外参和极线矫正，不负责二维码或逐管手工配准。
3. 检查管径、颜色和共同管长方向。必要时在模型预览中选择自动方向、X/Y/Z 或输入共同方向；不需要为每根管指定图像区域。
4. 点击“双目抓拍”，等待相机预热和画面稳定，确认左右目都露出连续的管道侧面，再同步抓拍。也可以分别导入已完成极线矫正的左右图。
5. 勾选左右图来自同一次同步拍摄，点击“保存基础现场”或“保存并评估”。程序首次自动创建 schema 2.0 的 `elevation_auto` manifest；报告、叠图、点云和日志写入同一现场包目录。

## 新增管道后的状态刷新

固定机位下安装新管道后，打开同一个基础现场并点击“状态刷新”：

1. 客户端重新打开双目抓拍，等待画面稳定后完成新的一对同步照片。
2. 程序追加新的 capture group，沿用模型、管道目录、标定和历史照片，不覆盖旧证据。
3. 程序自动重新计算局部深度、直径、立面相对布局和三态结果。报告记录刷新请求时间、左右目拍摄时间和分析完成时间。

## 自动识别和证据

现场工作台不提供逐管拖框、二维码定位、颜色配置流程或手工观察到模型的绑定。照片中的证据框由算法生成，右键平移、滚轮缩放只用于查看。可选的“局部建模”后端为自动圆柱/平行局部、仅双目深度几何和平行局部条带；后端通过 `pipe_twin/recognition/` 注册和替换，现场 manifest 仍保持统一。

报告会把每根模型管标记为 `INSTALLED`、`NOT_INSTALLED` 或 `UNKNOWN`。双目左右不一致、有效深度不足、局部被遮挡、直径超出模型范围或存在多个相近布局时，结果保持 `UNKNOWN`，不会用颜色单独给出确定身份。未安装判断还需要连续独立采集的可靠空位证据。

## 标定复用边界

同一台相机、镜头、分辨率、裁剪和左右布局下，已通过 `validated=true`、`rectified=true` 门禁的标定可以反复使用，不需要每次抓拍前重新标定。更换上述图像几何条件或发现极线/深度质量失效时，才重新运行棋盘格向导。原厂资料目录 `doc/双目测距、深度图、标定代码/` 只作为参数和格式参考，不会被现场程序直接执行。

## 日志和现场文件

CLI、GUI、抓拍和识别都会写结构化 JSONL 日志：

```text
logs/pipe_twin.log.jsonl
```

现场包至少包含 `manifest.json`、左右照片哈希、模型副本、识别报告、`surface_audit` 和算法生成的证据文件。照片素材可以留在现场证据目录，不需要提交 Git；功能代码、配置格式和测试应提交 Git。

## 当前清理边界

- 现场工作台和现场数据包只接受 DXF/STL 自动立面；旧 `elevation_depth` 逐管区域包会被拒绝。
- 3DM/3MF、二维码绝对配准和逐管手工框选已从现场操作入口移除。仓库中保留的旧解析器和合成资产只服务离线回归，不属于当前现场输入。
- 本版本不包含分区分析。后续如增加分区，应设计为可选的分区级 ROI、独立配准、结果合并和审计流程，不能恢复逐管手工框选。

## 软件验证

```powershell
python -m pytest -q
python -m compileall -q pipe_twin
```

真实相机的毫米精度仍需在现场有照明、左右目同时看到连续管道侧面的条件下复核；合成回归只验证软件链和安全门禁。
