# 从远程电脑直接下载双目照片和日志

远程主机仍用 `capture-stereo` 连接自己的 USB 双目相机。控制端现在可以通过 Tailscale 内的 HTTP 文件服务直接下载完整采集目录，无需 SSH 或 GitHub 中转。

## 控制端一条命令

在项目根目录运行：

```powershell
python -u -m pipe_twin fetch-stereo `
  --url http://100.103.31.118:8765/field-20260915-100331/ `
  --output-dir outputs/remote_fetch/field-20260915-100331
```

URL 是包含 `evidence_manifest.json` 的一次采集目录，而不是只有目录列表的服务器首页。清单的 `files` 每项需要 `path`、`size_bytes`、`sha256`；已有交接任务要求的清单可以直接使用。

命令会：

- 直接连接指定地址，不使用系统 HTTP 代理；
- 下载清单列出的全部原图、报告、日志，保持相对目录；
- 逐文件检查大小与 SHA-256，仅在校验通过后替换本地文件；
- 重复执行时复用已校验的文件，损坏或未下载完成的文件重新下载；
- 比较下载前后的清单，源数据变化时明确失败；
- 把下载报告写到输出目录旁的 `<目录名>.fetch.json`，避免混进原始证据目录。

下载后原始 `capture.json` 的 `rectified=false`、`calibration_validated=false` 保持不变。下载校验通过只表示文件完整，不表示标定、深度或管道状态判断通过。

## 远程主机的现有服务

当前用户提供的文件服务地址是 `http://100.103.31.118:8765/`，根目录对应 `D:\pipe_twin_runs`。它通过 Python HTTP 文件服务器提供 GET 下载。

**这是已经保存的照片，不是实时视频。** 这个服务不能远程执行命令、触发拍照、修改相机设置或运行标定。需要新照片时，远端先运行 `capture-stereo` 并生成新的证据清单，再从控制端下载新运行目录。固定棋盘或场景不动不会自行生成新的采集。

例如 `field-20260915-100331` 的照片记录时间为 2026-09-15；即使今天能够下载，也不能把它们称为今天的实时画面。

当 `evidence_manifest.json` 已更新或切换了运行目录，请使用新的本地目录。只有同一份源清单可以继续原目录下载，避免混淆两次采集。

## 结果检查

1. `<目录名>.fetch.json` 应为 `status=PASS`，没有失败文件，且 `manifest_unchanged=true`。
2. 打开某次 `attempt-*/capture.json`，检查实际成功照片对数、停止原因、时间、尺寸和原始/矫正标识。
3. 检查 PNG 能否解码，左右图是否成对，并阅读本次日志；接口可访问不能代替照片质量检查。
4. 需要立面深度与 STL 配准时，再提供当前设备和分辨率对应的有效标定与模型。没有棋盘或标定时，不把普通管道照片伪装成标定照片。
