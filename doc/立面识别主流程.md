# DXF / STL 双目立面识别主流程

这条流程面向固定机位、彼此平行的管道。DXF 是首选的侧立面模型来源，STL 作为同一流程的网格输入；3DM/3MF、二维码定位和手工框选只保留给旧包或完整三维模式，不再放在日常识别主线上。

## 第一次配置

1. 启动 GUI，在“基础立面评估”中导入 `管道布置.dxf`。程序读取实体和图层，自动生成管道目录、默认流水号、管径和颜色；实体没有显式颜色时才使用图层颜色。核对管径和共同管长方向，保存基础现场。
2. 在“② 相机标定”中选择与当前相机、镜头、拼接布局和每目分辨率一致的真实标定 JSON。标定必须包含 `validated=true`、`rectified=true`、毫米基线和 `R1/R2/P1/P2` 矫正结果。工作台会把标定 ID 与矫正配方绑定。
3. 只有在没有可用标定包，或更换相机、镜头、分辨率、裁剪/左右布局后，才打开“重新标定（仅换设备/分辨率）”。棋盘格向导生成的是相机内参和极线矫正；它不自动完成 CAD 世界坐标配准。
4. 第一次抓拍前确认左右目都能看到连续的管道侧面，且相机预览、棋盘格窗口没有被其他程序占用。点击“③ 双目抓拍”，再点击“保存并评估”。

基础立面模式不要求二维码。识别会在左矫正相机坐标中，从共同可见的局部截面建立模型和现场的相对布局；需要绝对 CAD 坐标或完整三维测量时，才另做二维码/控制点配准。

## 新增管道的日常刷新

现场物理环境新增管道后，在同一个基础现场点击“状态刷新”：

1. 客户端重新打开双目抓拍窗口；等待画面稳定后点击“同步抓拍并使用”。
2. 程序创建新的 capture group，沿用模型、标定、管道目录和旧历史，不覆盖旧照片。
3. 程序自动执行深度、局部识别、相对布局匹配和三态判断。报告保存请求时间、左右目实际拍摄时间和分析完成时间。

因此，新增管道不需要重新导入 DXF，也不需要重新标定；只有上述硬件/图像几何条件改变时才回到第一次配置。

## 识别算法模块

识别入口已经从 `elevation_auto.py` 拆到 `pipe_twin/recognition/`。分析器只接收一个统一的 `surface` 结果，再负责模型配准、状态历史和证据输出。内置后端为：

| manifest 值 | 用途 |
| --- | --- |
| `auto` | 先做严格局部圆柱，候选为空或搜索被遮挡截断时，受限回退到平行局部条带 |
| `cylinder` | 只使用双目局部圆柱拟合 |
| `parallel_strip` | 适合圆弧被棋盘或遮挡切断的平行侧面；颜色只作候选提示 |
| `geometry_only` | 只使用双目深度，沿共同管轴截断左右目共同可见局部；颜色不参与候选生成或身份判定 |

每个结果的 `surface.audit` 会记录请求的后端和实际使用的后端。直径和相对立面距离是身份主依据，颜色只做候选分层、审计或显示。双目几何不一致、候选搜索截断、局部不足或布局有歧义时，结果保持 `UNKNOWN`。

后续算法可以在进程启动时注册，不需要修改状态机或 manifest 写入器：

```python
from pipe_twin.recognition import register_recognizer

def my_backend(left, right, depth, calibration, pipe_specs):
    # 返回至少 {"observations": [...]}，可附带 audit / point_cloud
    return {"observations": [], "audit": {"implementation": "my-v1"}}

register_recognizer("my-v1", my_backend)
```

随后把 `registration.local_observation_mode` 设为 `my-v1` 即可。未注册的算法名称会在建档和载入时拒绝，避免现场包静默执行未知代码。

## 标定状态的当前结论

仓库中的 `doc/双目测距、深度图、标定代码/` 是原厂参考脚本和资料，不是最终现场标定文件。现场报告记录的候选 `field-chess-fb5dc0f71ee5` 沿用了历史 15 姿态结果，分辨率为每目 `1920×1080`、保存基线约 `60.6446 mm`；本轮固定棋盘照片只做兼容性检查，没有重新求解完整标定。

对同一台汇博视捷 60 mm 双目、同一 `3840×1080` 拼接流和同一镜头设置，这份标定通过 `validated/rectified` 门禁后可以复用，**无需每次拍照前重复标定**。它的 `registration_validated=false` 表示 CAD 绝对配准尚未验收，不表示相机内参和双目矫正需要重做；基础立面相对布局模式仍可运行。更换设备、分辨率、裁剪、左右顺序、镜头或发现矫正/深度质量失效时，才必须重新标定并重新绑定配方。

当前仓库不提交 `outputs/measurement_workbench/calibration_current.json` 等现场私有文件。办公室 GUI 的标定状态栏会显示实际加载的 `calibration_id`、分辨率、基线，以及“相机标定已完成，无需重复”或“CAD 配准未确认”。只有状态栏加载了真实现场 JSON，才能把上述复用结论应用到那台设备。

## 可以简化的旧入口

- 日常 DXF 侧立面不再经过“先载入现场清单”：导入 DXF 后直接在基础立面窗口保存现场，manifest 由程序创建。
- 不再把 3DM/3MF、二维码、手工区域框选作为 DXF 主流程的必需步骤；它们仍能打开旧包，避免破坏历史数据。
- “设置颜色”和“同径统一颜色”只影响显示和颜色辅助，不参与管道身份的最终判定；同一管径颜色配置不是一次新的识别流程。
- 原厂脚本只用于追溯采集格式和参数，不能直接运行来替代当前标定、深度和日志门禁。

每次运行仍会写入 `logs/pipe_twin.log.jsonl`，现场包保存 manifest、左右图哈希、识别审计和报告；原始照片可留在现场证据目录，不需要提交 Git。
